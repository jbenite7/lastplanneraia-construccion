## API and Service Signatures

### Scope and stores

```php
final readonly class CnpScope
{
    public function __construct(
        public int $projectId,
        public string $projectName,
        public string $dbPrefix,
        public string $area,
        public int $week,
        public int $maxWeek,
        public string $weekStart,
        public string $weekEnd,
        public bool $confirmed,
    ) {}
}

interface CnpReadStore
{
    public function readProfessionals(CnpScope $scope): array;
    public function readCauseCatalog(CnpScope $scope): array;
    public function readRows(CnpScope $scope): array;
}

interface CnpWriteStore extends CnpReadStore
{
    public function transaction(callable $work): mixed;
    public function lockWeek(CnpScope $scope): array;
    public function lockRow(CnpScope $scope, int $rowId): ?array;
    public function updateClassification(CnpScope $scope, int $rowId, array $values): void;
    public function reactivate(CnpScope $scope, int $rowId): void;
}
```

`DatabaseCnpStore` resolves table names only from `CnpScope::$dbPrefix`, which itself comes from the
authenticated project scope. Every operational query includes `project_id`. `readRows()` selects
only the fields listed by the spec and orders by `Consecutivo_En_Programa, row_id`.

### Pure services

```php
CnpPriorityResolver::resolve(mixed $overdue, mixed $critical): array;
CnpPriorityResolver::legend(): array;

CnpCatalogService::normalize(string $area, array $rows): array;
CnpCatalogService::resolveCause(string $area, array $rows, int $causeId): array;
CnpCatalogService::matchHistorical(string $area, array $rows, ?string $category, ?string $cause): ?array;

CnpActionPolicy::resolve(
    bool $canView,
    bool $canEdit,
    bool $weekAllowsEdit,
    bool $confirmed,
    bool $catalogAvailable,
): array;

CnpVersion::fromRow(int $projectId, int $week, array $row): string;
```

The action result is always:

```php
[
    'edit' => ['allowed' => true, 'reasonCode' => null],
    'reprogram' => ['allowed' => false, 'reasonCode' => 'WEEK_CONFIRMED'],
]
```

### Application services

```php
CnpContextService::get(CnpScope $scope): array;
CnpQueryService::list(CnpScope $scope): array;

CnpMutationService::update(
    CnpScope $scope,
    int $rowId,
    string $version,
    array $responsibleSelection,
    array $classificationSelection,
    ?string $observations,
): array;

CnpMutationService::reprogram(
    CnpScope $scope,
    int $rowId,
    string $version,
): array;
```

The controller resolves scope/capability/CSRF, parses strict JSON and maps domain exceptions to the
stable status/code table. It contains no SQL, role matrix, category array or mutation logic.

### Frontend gateway

```ts
export function obtenerContextoCnp(signal?: AbortSignal): Promise<ContextoCnp>;
export function obtenerActividadesCnp(signal?: AbortSignal): Promise<ActividadesCnp>;
export function guardarActividadCnp(
  entrada: GuardarActividadCnp,
  csrfToken: string,
  signal?: AbortSignal,
): Promise<ActividadCnpActualizada>;
export function reprogramarActividadCnp(
  entrada: ReprogramarActividadCnp,
  csrfToken: string,
  signal?: AbortSignal,
): Promise<ResultadoReprogramacionCnp>;
```

Exact routes are `/api/cnp/context`, `/api/cnp/activities`, `/api/cnp/activity` and
`/api/cnp/reprogram`. Mutations use `Content-Type: application/json` and `X-CSRF-Token`; neither
request includes week/project/area/db/role or free-form category/cause.
