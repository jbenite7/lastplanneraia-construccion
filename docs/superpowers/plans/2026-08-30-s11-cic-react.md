**Goal:** migrate `/programacion-semanal/cic` from VIEW-36, DataTables, two duplicated modal forms
and shared global JavaScript to a native React CIC surface with pure reads, persisted/projected
providers, the exact 59-question catalog, server-effective discipline permissions, eight-presence
cadence, responsive table/cards and transactional individual evaluation, without changing RLS,
schema, live data or BI behavior during verification.

**Architecture:** T01 supplies shell/session/project/week/theme/navigation and owns week creation;
S08 supplies weekly presence/materialization at close; S09/S10 complete sibling navigation. S11
adds an explicit CIC application boundary: a code-owned questionnaire catalog, pure
presence/projection/cadence/scoring/integral policies, separated read/write stores and exactly three
HTTP contracts. GETs never call writes. The first explicit save materializes one projected provider
under lock; existing edits recalculate only that provider from the affected week forward. React
validates every wire shape with strict Zod, keeps one normalized provider store and mounts a table
at 768+ or native cards below 768. VIEW-36 remains a rollback path until all gates pass.

**Tech Stack:** PHP 8.3 in Docker Compose, React 19, TypeScript 7, react-router-dom 7, Vite 8, Zod 4,
Vitest 4, Testing Library, Playwright 1.61, Axe and AIA design-system tokens.

## Exact Contracts to Implement

### Server scope

```php
final readonly class CicScope
{
    public function __construct(
        public int $projectId,
        public string $projectName,
        public string $area,
        public int $cutWeek,
        public int $maxWeek,
        public ?string $startDate,
        public ?string $endDate,
        public bool $confirmed,
    ) {}
}
```

Controllers build scope only from authenticated server context. Request JSON/query never supplies
project, prefix, role or week as authority.

### Answer and metric values

```php
enum CicAnswerValue: string
{
    case NotRated = 'not-rated';
    case Zero = 'zero';
    case Half = 'half';
    case Full = 'full';
    case NotApplicable = 'not-applicable';
}
```

Exact mappings:

```text
not-rated <-> NR
zero <-> 0
half <-> 0.5
full <-> 1
not-applicable <-> NA
```

`CicMetricValue` is discriminated: `not-rated`, `not-applicable`, or `scored` with finite `0..1`.
Question IDs are stable (`mdo.quality.1`, `si.administration.6`); storage columns never cross HTTP.

### Discipline, integral and cadence

```php
CicDisciplineScore::calculate(array $answers): CicMetricValue;

CicIntegralCalculator::calculate(
    CicMetricValue $pac,
    array $disciplines
): CicMetricValue;

CicCadencePolicy::evaluate(
    int $distinctProviderWeeks,
    array $disciplines
): CicCadenceDecision;
```

Discipline score ignores NR/NA numerically; all NR is `not-rated`; no numeric with at least one NA is
`not-applicable`; otherwise numeric average rounded three decimals. Integral base weights are
PAC `.30`, quality `.20`, GSA `.20`, SST `.20`, administration `.10`, normalized across available
dimensions. Cadence is due only for positive multiples of eight; only `not-rated` is missing.

### Provider target union

```text
{mode: existing, evaluationId: positive-int}
{mode: projected, subcontractorId: positive-int}
```

Existing targets resolve within project and cutoff. Projected targets must have eligible presence,
supported/compatible master metadata and no equivalent persisted row under lock.

### HTTP routes

```text
GET  /api/cic/context
GET  /api/cic/providers
POST /api/cic/evaluation
```

All envelopes/errors follow the spec exactly. No lookup/history/export/batch/catalog endpoint is
added.

### Frontend gateway

```ts
export interface CicGateway {
  context(signal?: AbortSignal): Promise<CicContextResponse>
  providers(signal?: AbortSignal): Promise<CicProvidersResponse>
  saveEvaluation(input: CicEvaluationRequest, csrfToken: string): Promise<CicEvaluationResponse>
}
```

The implementation delegates to `cliente.ts`; no component imports the HTTP client or calls fetch.
