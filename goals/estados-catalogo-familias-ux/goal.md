# Estados claros para familias y contratos

El objetivo es que usuarios finales y administradores entiendan por qué una familia, alias o elemento contractual se comporta de cierta forma en Listado, Contratos y PDC. La UI debe reemplazar explicaciones ambiguas como `Inactivo` por estados accionables, motivos claros y próximos pasos.

La comprensión compartida está en `facts.md`.

El plan de ejecución está en `plan.md`.

Done condition: un usuario puede ver por qué una familia no se aplicó, qué hacer después, y un Admin puede corregir catálogo, reglas u opciones contractuales sin tocar SQL. El flujo Listado -> Contratos -> PDC queda verificado con evidencias E2E y reporte completo de catálogo.
